Команда React рада поделиться несколькими новостями:

1. Мы начали работу над релизом React 18, который станет нашей следующей основной версией.
2. Мы создали рабочую группу для подготовки сообщества к постепенному внедрению новых функций в React 18.

Эти обновления в первую очередь предназначены для сопровождающих сторонних библиотек. Если вы изучаете, преподаете или используете React для создания пользовательских приложений, вы можете безопасно игнорировать этот пост. ## Что нового в React 18 {/*whats-coming-in-react-18*/}

Когда он будет выпущен, React 18 будет включать готовые улучшения (например, [автоматическую пакетную обработку](https://github.com/reactwg/react-18/discussions/21)), новые API (например, [`startTransition`](https://github.com/reactwg/react-18/discussions/41)) и [новый потоковый серверный рендерер](https://github.com/reactwg/react-18/discussions/37) с встроенной поддержкой `React.lazy`.

Эти функции стали возможны благодаря новому механизму выбора, который мы добавляем в React 18. Он называется «конкурентный рендеринг» и позволяет React одновременно подготавливать несколько версий пользовательского интерфейса. Это изменение в основном скрыто от глаз, но оно открывает новые возможности для улучшения как реальной, так и воспринимаемой производительности вашего приложения.

Если вы следили за нашими исследованиями будущего React (мы не ожидаем, что вы это делали!), вы могли слышать о чем-то под названием «конкурентный режим» или о том, что он может сломать ваше приложение. В ответ на эту обратную связь от сообщества мы переработали стратегию обновления для постепенного внедрения. Вместо режима «все или ничего» конкурентный рендеринг будет включен только для обновлений, инициированных одной из новых функций. На практике это означает, что **вы сможете внедрить React 18 без переписывания кода и пробовать новые функции в удобном для вас темпе.**

## Стратегия постепенного внедрения {/*a-gradual-adoption-strategy*/}

Поскольку конкурентность в React 18 является опциональной, нет существенных готовых изменений, нарушающих поведение компонентов. **Вы можете обновить React 18 с минимальными изменениями или без них в коде вашего приложения, приложив усилия, сравнимые с обычным основным релизом React**. Основываясь на нашем опыте преобразования нескольких приложений в React 18, мы ожидаем, что многие пользователи смогут обновиться в течение одного дня.

Мы успешно внедрили конкурентные функции в десятки тысяч компонентов в Facebook, и по нашему опыту большинство компонентов React «просто работают» без дополнительных изменений. Мы стремимся обеспечить плавное обновление для всего сообщества, поэтому сегодня мы объявляем о рабочей группе React 18.

## Работа с сообществом {/*working-with-the-community*/}

Мы пробуем кое-что новое для этого релиза: мы пригласили группу экспертов, разработчиков, авторов библиотек и преподавателей из сообщества React для участия в нашей [Рабочей группе React 18](https://github.com/reactwg/react-18), чтобы предоставить обратную связь, задать вопросы и сотрудничать по релизу. Мы не смогли пригласить всех желающих в эту первоначальную небольшую группу, но если этот эксперимент окажется успешным, мы надеемся, что в будущем их будет больше!

**Цель рабочей группы React 18 — подготовить экосистему к плавному, постепенному внедрению React 18 в существующие приложения и библиотеки.** Рабочая группа размещена на [GitHub Discussions](https://github.com/reactwg/react-18/discussions) и доступна для публичного чтения. Члены рабочей группы могут оставлять отзывы, задавать вопросы и делиться идеями. Основная команда также будет использовать репозиторий обсуждений для обмена результатами своих исследований. По мере приближения стабильного релиза вся важная информация будет также публиковаться в этом блоге.

Для получения дополнительной информации об обновлении до React 18 или дополнительных ресурсов о релизе см. [пост с анонсом React 18](https://github.com/reactwg/react-18/discussions/4).

## Доступ к рабочей группе React 18 {/*accessing-the-react-18-working-group*/}

Каждый может читать обсуждения в [репозитории рабочей группы React 18](https://github.com/reactwg/react-18).

Поскольку мы ожидаем первоначальный всплеск интереса к рабочей группе, только приглашенные члены смогут создавать или комментировать темы. Однако темы полностью видны публике, поэтому все имеют доступ к одной и той же информации. Мы считаем, что это хороший компромисс между созданием продуктивной среды для членов рабочей группы и поддержанием прозрачности с более широким сообществом.

Как всегда, вы можете отправлять сообщения об ошибках, вопросы и общие отзывы в наш [трекер проблем](https://github.com/facebook/react/issues).

## Как попробовать React 18 Alpha сегодня {/*how-to-try-react-18-alpha-today*/}

Новые альфа-версии [регулярно публикуются в npm с использованием тега `@alpha`](https://github.com/reactwg/react-18/discussions/9). Эти релизы собираются на основе последнего коммита в нашем основном репозитории. Когда функция или исправление ошибки будут объединены, они появятся в альфа-версии на следующий рабочий день.

Между альфа-релизами могут быть существенные изменения в поведении или API. Пожалуйста, помните, что **альфа-релизы не рекомендуются для использования в общедоступных производственных приложениях**.

## Прогнозируемый график выпуска React 18 {/*projected-react-18-release-timeline*/}

У нас нет конкретной даты выпуска, но мы ожидаем, что потребуется несколько месяцев обратной связи и итераций, прежде чем React 18 будет готов для большинства производственных приложений.

* Альфа-версия для библиотек: доступна сегодня
* Публичная бета-версия: не менее нескольких месяцев
* Release Candidate (RC): не менее нескольких недель после бета-версии
* Общая доступность: не менее нескольких недель после RC

Более подробная информация о нашем прогнозируемом графике выпуска [доступна в рабочей группе](https://github.com/reactwg/react-18/discussions/9). Мы будем публиковать обновления в этом блоге, когда приблизимся к публичному релизу.
